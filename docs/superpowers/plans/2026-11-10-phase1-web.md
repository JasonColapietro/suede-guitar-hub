# Sell-First Funnel, Phase 1 (Web) Implementation Plan

> **Owner decision, 2026-11-10: measurement is deferred.** No PostHog and
> no usage-event collection on either platform until there is a paying
> user. Skip the tasks marked DEFERRED below. Code that other tasks call
> to send a funnel event becomes a no-op with the same signature, so it
> can be switched on later. The App Store privacy label and manifest
> change only for account data, not usage data.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** guitarhub.org carries one promise, gives each visitor one free module, takes a $79 Stripe payment that unlocks web and iPhone, collects email through a 30-day plan magnet, and measures every funnel step.

**Architecture:** The existing Supabase account ledger gains Stripe as a second purchase source matched by verified email, plus tables for the free-module choice and leads. Paid lesson pages stay server-gated; the free module and the newly locked tools are gated in the client so their pages stay static and indexable. All new server logic follows the repo's pattern: a `create…Handlers(deps)` factory tested with doubles, and a thin route file.

**Tech Stack:** Next.js 16 (App Router), React 19, Supabase (`@supabase/ssr`, `@supabase/supabase-js`), Stripe Checkout, Resend REST API, PostHog (`posthog-js`), Vercel Cron, `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-10-sell-first-funnel-design.md` and the fixed contract `docs/superpowers/plans/2026-11-10-phase1-shared-contract.md` (both in `guitarhub-ios`). All file paths below are in the `suede-guitar-hub` repo.

## Global Constraints

- Read `AGENTS.md` first. Before writing any Next.js code read the matching guide in `node_modules/next/dist/docs/`; this Next version differs from older ones.
- Founder copy rule (`AGENTS.md`): lead with what the buyer can achieve; no hedging or self-disqualifying wording.
- Promise, verbatim: "Play real chords and improvise your first solo in 30 days."
- Guarantee, verbatim: "If after 90 days you are not playing chords and improvising, you get a full refund."
- Price: `$79` one time, shown before tax, read from `LIFETIME` in `lib/site.ts`. Never typed in a page.
- No copy says the app hears or scores chords. It scores single notes and timing.
- No cookie banner, consent pop-up or consent checkbox. PostHog runs with in-memory persistence and sets no cookie.
- Voice on the web links to Suede Sing (`STRUMLY.sing`) and is never described as free.
- No existing buyer loses access. No indexed page leaves the sitemap or gains `noindex`.
- Endpoint paths, JSON shapes, event names and module ids come from the shared contract, unchanged.
- Tests: `node:test` in `tests/*.test.ts`. Single file: `T tests/<name>.test.ts`, where `T` is `node --test --experimental-strip-types --disable-warning=ExperimentalWarning --import ./tests/register-aliases.mjs`. Whole suite: `npm test`. Before each commit also run `npm run lint`.
- New dependencies are pinned to an exact version, like the existing ones.
- **Branch rule:** every push to `main` deploys production (`vercel.json` `ignoreCommand`), and previews are not built. Do all tasks on one branch, `sell-first-web`. Merge only after Task 17 is done and the iPhone update that honours web purchases is approved. Verify locally with `npm run build && npm start`.
- For Stripe, PostHog, Resend, Supabase Auth and Vercel Cron, read the current official docs before writing the call. This plan fixes what to send and what to expect, not the SDK method shapes.

## Review Focus

1. **Buyer signs in with a different email, or different letter case, than the one used at Stripe Checkout.** Expected: matching ignores case and surrounding space; the success page shows the checkout email and pre-fills sign-in with it; an unverified email never unlocks. Tests in Tasks 3 and 5.
2. **Stripe webhook arrives late, twice, or out of order; a refund is partial.** Expected: access exists as soon as the success page loads; a repeated event changes nothing; a partial refund keeps access; a refund for a payment not yet recorded answers non-2xx so Stripe retries. Tests in Tasks 5 and 6.
3. **PostHog is blocked by an ad blocker, or its key is unset.** Expected: every button, the paywall and checkout work; no error reaches the visitor. Tests in Tasks 9 and 10.
4. **Browser storage is unavailable or cleared, or a guest who chose a module signs in to an account that already has a different one.** Expected: placement still opens the module for that visit; the server's choice wins and replaces the local one. Tests in Tasks 1 and 11.
5. **The same email is submitted to the magnet twice, an unsubscribed person submits again, or Resend is down.** Expected: no second copy of email 1; an unsubscribed lead stays unsubscribed; the lead is stored and the send is retried by the daily job; a PDF download is never blocked by our outage. Tests in Tasks 13 and 14.
